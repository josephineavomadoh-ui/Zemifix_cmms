## 7. Current Sidebar / Topbar Structure and Problems

### Sidebar (`src/components/layout/Sidebar.tsx`)

**Structure:**
- Fixed position, navy (`#080E29`) background, 256px wide / 76px collapsed
- Logo at top (3-variant image asset via `Logo` component)
- 5 navigation groups: Workspace, Maintenance, Customers & service, Supply & finance, Administration
- Each item: icon + label, active state = orange left-border stripe + white/10 background
- Collapse/expand button (desktop only)
- Mobile overlay with backdrop
- User avatar initials + name + role at bottom
- Logout button

**Problems:**
1. **Duplicate icon usage**: `Boxes` is used for both "Asset register" and "Inventory". `Building2` is used for "Locations", "Stores", and "Organization". `FileInput` is used for "Requisitions" and "Import data". `HardHat` is used for "Suppliers" and "Workers". Visually confusing — user cannot distinguish items by icon alone.
2. **Too many items in Supply & finance group**: 10 items without sub-grouping makes the section unreadable. Procurement sub-items (Requisitions, POs, Suppliers) could be collapsible.
3. **Asset navigation is split**: "Assets" (href: `/assets` → redirect) and "Asset register" (href: `/dashboard/assets`) both appear separately. This is a navigation artefact of an earlier path restructure. The sidebar shows both, which is confusing.
4. **Active state detection**: `pathname.startsWith(`${item.href}/`)` will mark `/dashboard` as active for `/dashboard/assets/categories` because `dashboard` starts with `dash`. Actually this is fine — it checks `item.href !== '/dashboard'`. However `/assets` redirect means that nav item never highlights correctly on `/dashboard/assets/*` paths.
5. **No collapsible groups**: All 5 groups are always fully expanded. With 29 nav items total, the sidebar requires scrolling on small screens.
6. **Font size**: `text-[12px]` is very small for nav labels; `text-[10px]` for group headings is barely readable.
7. **Notifications not in sidebar**: The notification bell is only in TopNav, which is fine architecturally, but no notification count badge in sidebar for mobile-first usage.

### TopNav (`src/components/layout/TopNav.tsx`)

**Structure:**
- Sticky, white background, 64px height
- Left: hamburger (mobile), page title + "ZemiFix operations workspace" subtitle
- Right: branch selector dropdown, NotificationHub, user avatar menu
- Branch list fetched from `/api/organization/branches`
- Profile menu: staff directory link, settings link, sign out

**Problems:**
1. **Page title is static lookup**: `pageTitles` record is hardcoded. Dynamic routes (`/work-orders/[id]`, `/dashboard/assets/[id]`) return generic "Work order details" / "Asset details" strings with no actual record context.
2. **Branch selector is decorative**: `setSelectedBranch` stores branch name in context but there is no evidence the selected branch is passed to API calls. Work orders, assets, etc. fetch without branch scoping from the topbar selection.
3. **No breadcrumb**: Only a flat page title. Deep routes like `/dashboard/assets/categories` show "Asset categories" without hierarchy context.
4. **No search bar**: The original design spec calls for search. TopNav has no global search input.
5. **"ZemiFix operations workspace" subtitle**: Static — does not adapt to context.
6. **Profile menu opens towards edge**: On narrow viewports the right-aligned dropdown can clip.

## 9. Layout Inconsistencies

1. **Two coexisting colour schemes**: ~11 pages use a dark theme (`slate-900` / `slate-800`); the shell, dashboard, and ~8 other pages use the correct light ZemiFix theme.

2. **Double Shell wrapping**: Several pages (`preventive/page.tsx`, `users/page.tsx`, `organization/page.tsx`, `reports/page.tsx`, `settings/page.tsx`, etc.) explicitly wrap their content with `<Shell>` despite `ApplicationFrame` already wrapping every non-standalone route in `<Shell>`. The Shell component contains a nested-shell guard (`isNested` context) that prevents double rendering — so it doesn't break, but the pattern is inconsistent. The dashboard and work-orders pages do NOT wrap in Shell themselves, relying on the frame correctly.

3. **No consistent page header pattern**: Some pages use `<PageHeader>` component; others inline their own header div with the same visual intent but different markup/spacing. The `PageHeader` eyebrow badge uses `bg-blue-50 text-blue-700` — a colour not in the ZemiFix palette.

4. **Inconsistent padding**: Dark-theme pages use `p-6 max-w-7xl mx-auto` as their outer container. Light-theme pages omit this (the shell's `main` already applies `p-4 md:p-6 lg:p-8` and `max-w-[1440px]`). The dark pages therefore have double-padding in the shell context.

5. **Alert pattern**: Dark pages use `bg-rose-500/10 border border-rose-500/20 text-rose-400` for errors. Light pages use `bg-rose-50 border border-rose-200 text-rose-800`. Two completely different patterns.

6. **Button pattern**: Dark pages use `bg-brand-orange hover:bg-brand-orange-hover`. Light pages use `bg-[#FF5B00] hover:bg-[#F95700]`. Both resolve to the same colour but inconsistently expressed.
